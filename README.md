# Smart AI Study Planner

## Run locally

From the repository root, serve `frontend` from localhost so browser storage and Web Crypto are available:

```powershell
python -m http.server 8000 --directory frontend
```

Open `http://localhost:8000/`. Stop the server with `Ctrl+C`. No npm install or build step is required. The site is a browser-only demo: study records stay in that browser, and accounts are not shared across browsers or devices. The local account flow hashes passwords in the browser, but it is not production authentication; use a throwaway password, never a real or reused one.

The neural 3D visuals load Three.js from jsDelivr when the scene is near the viewport. If WebGL or the CDN is unavailable, a CSS illustration remains as a fallback.

## Current functionality and service boundaries

The frontend provides local task and subject management, calendar views, notes, notifications derived from tasks, a focus timer, browser-local profile/settings, dashboards, and analytics based on saved browser data. Planner drafts are generated locally from form values and saved records; they are not generated by an AI model. Browser storage can be cleared by the user or browser, and this demo does not synchronize records between users or devices.

The PHP API/auth/config/helper/middleware files under `backend` are empty placeholders, both SQL files under `database` are empty, and `ai/app.py` plus `ai/requirements.txt` are empty. No server API, schema, credentials, or running AI service is supplied. Consequently:

- **Real authentication:** implement and deploy server-side registration/login/session endpoints, password hashing/verification, secure session or token handling, validation, and authorization. Replace the browser-only auth flow and add deployment configuration.
- **MySQL persistence:** define and apply a schema for users and their study records; configure protected database credentials and connection handling; implement authorized CRUD APIs; and migrate or explicitly import each browser's local data.
- **Shared notifications:** implement authenticated server-side notification storage and APIs, plus a delivery/update mechanism if real-time notifications are needed. Current notifications are derived locally from tasks.
- **Live AI study generation:** implement a backend generation endpoint, configure a model/provider and secrets securely on the server, validate its input/output, and connect the planner UI. No model call occurs in this demo.
- **Server-side analytics:** add persisted, authorized session/task events and aggregation endpoints; current analytics calculate from the current browser's saved records only.

These are backend implementation requirements, not working features in the current repository. Do not treat the browser-only demo login or local records as secure, shared, or backed up.
